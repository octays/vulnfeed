# 飞书群个人回执

确认单直接发送到所有启用的接收群（团队概念已移除），无需预设确认人。发送时为每个团队创建任务，群卡片包含漏洞或公告详情以及问卷表单：影响状态、判断依据/影响范围（50 字以内；选择「待排查」时依据可留空，无影响/有影响必须填写，由服务端按状态校验）。按钮为「提交（可覆盖变更）」，每人可重复提交覆盖自己的答案。卡片不展示固定"确认团队"、填写说明和团队/单据状态行——状态由回执统计与明细表格表达；处置说明在网页查看。卡片不展示固定"确认团队"，也不需要填写人选择团队——**提交人的团队由系统在提交后自动解析为其飞书所属部门（第一个部门）**，依赖应用具备通讯录用户组织架构与部门信息读取权限；解析完成前展示任务团队作为回退，解析失败（无权限/无部门/用户不可见）时保留回退并周期重试。

卡片回调经过飞书长连接和桥接鉴权，服务端核对应用、租户、发送记录、消息 ID、群 ID 及团队群绑定。通过校验后，按任务、应用、租户、Open ID 保存每人的最新回执；同一个人在不同应用下的 Open ID 无法自动合并。人员姓名按回退链展示：管理员绑定/通讯录查询的姓名 → 群成员缓存中的姓名 → Open ID。

同一人在卡片重新提交可修改自己的回执；管理员可在网页修改或软删除，只保留每人最终状态（回执事件表仅用于回调去重，不做变更审计）。同步任务设置中的「允许填写人删除自己的回执」开关（默认关闭）对所有确认单统一生效：开启后卡片表单下方出现「删除我的回执」按钮，填写人可撤回自己的提交（软删除、留审计、按事件 ID 去重），关闭后按钮消失且删除回调被拒绝，填写人只能通过再次提交覆盖变更。重复回调按事件 ID 去重；群卡片以问卷形式回写采集结果：显示回执统计（有影响／待排查／无影响人数）和按 有影响→待排查→无影响 排序的明细表格（最近 20 条，团队／人员／结论／说明／提交时间为本地时区），并保留提交入口，完整回执在网页查看。若飞书拒绝表格组件，发送与更新自动降级为文本明细，回执数据不受影响。任务汇总为有影响优先，其次待排查，全部无影响时显示无影响；新的有影响回执会重新打开需处置的状态。管理员决定何时关闭确认单，关闭后不能继续提交或修改。

不再维护确认人白名单。能操作指定群原卡片的用户可提交；本实现校验卡片来源和群绑定，但不调用飞书接口独立核验操作者的当前群成员身份。请确保群的访问范围符合团队要求。

升级迁移保留原有事件，将每个用户的最后一条旧回执作为当前回执，并将进行中确认单的已发送卡片加入刷新队列。卡片更新失败会重试，并在网页显示失败状态。历史数据不会因切换模式被删除。

如果飞书返回消息已撤回，系统会停止刷新该消息并在网页标记。管理员可在确认单中点击“发送确认卡片”重新发送；原消息和请求标识会保留在撤回记录中。重新发送使用当前回执汇总，不丢失已登记结果。

每个接收群可配置「@ 提醒人员」（feishu_chat.mention_open_ids）：发送/重发确认卡片与催办卡片时，卡片顶部以 <at> 标签提醒这些人（飞书渲染为蓝色 @名字，无需额外权限）。人员从已提交回执的名单中选择或手动粘贴 Open ID。

人员姓名与团队均按提交人逐一解析：姓名来自单用户通讯录接口（GET /contact/v3/users/:open_id，user_id_type=open_id、department_id_type=department_id）；团队（部门）优先取用户对象 department_ids 的首个部门，当该字段被字段级权限隐藏时自动回退到部门缓存——由部门树（GET /contact/v3/departments/0/children?fetch_child=true）与按部门拉成员（users/find_by_department）构建的 open_id→部门 映射，每小时刷新（feishu_department / feishu_department_member 表）。姓名写入 display_name（留审计），部门写入 team；管理员预先绑定的身份优先，解析失败周期重试。不依赖群成员列表缓存：应答率（N/M）、未回结名单及基于名单的手动催办已停用；自动催办退化为“仍无人回执时每 24 小时提醒一次、每任务最多 3 次”。管理员可在确认单详情导出全部当前回执 CSV。

自动催办默认关闭，可在同步任务设置中开启：对进行中且仍有未回执（或未同步成员时无人回执）的任务，每 24 小时自动发送一次催办卡片，每个任务最多 3 次；全部群发送失败时不消耗次数，顺延一个周期重试。手动催办与自动催办共用同一发送逻辑。问卷卡片是唯一卡片模式；升级前已投递的旧布局卡片不会自动重渲染，需要新版式时对旧单据重新发送。
